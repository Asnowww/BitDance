# BD-F M2 必要跨模块验证清单

更新时间：2026-06-10

最新验证状态：2026-06-10 已在本地 `8082` 后端、`5173` 前端、SSH 数据库隧道和本地 Redis 环境下复核。`trial/order/checkin` 三类来源已接入评价来源核验；发布评价、我的评价、教练/商家回复队列已通过 UI 验证。

## 说明

- 本清单只列 M2 中不能仅靠当前评价模块独立闭环验收的功能点。
- 判断标准不是“前端能不能显示”，而是“是否必须借助其他模块的业务事实、角色权限或审核链路，才能证明功能成立”。
- 本清单适合分配给联调阶段使用。

## 使用口径

- `必须跨模块验证`：不能只靠 M2 页面和 M2 接口本身完成有效验收。
- `可补库辅助准备`：允许先往数据库注入前置事实，再走接口或页面完成验证。
- `不能只补库代替验收`：即使能补库，也不能把补库结果直接当成功能已通过。

## 分项验证说明

### 1. `M2-F04` 评价权重分层

- 当前真实依赖：
  - `trial_booking`
  - 未来的 `workshop_order`、`workshop_checkin`
  - 用户账号时间等 `M3` 数据
- 当前代码现状：
  - 已接 `trial`
  - 已接 `order`
  - 已接 `checkin`
- 推荐验证方式：
  - 先准备一条课程或舞室试听记录
  - 再通过写评价接口提交带 `sourceType=trial` 的评价
  - 对比普通评价与已验证评价的 `isVerified`、`weightFactor`
  - 再用 Workshop 订单/签到提交带 `sourceType=order/checkin` 的评价，核对 `isVerified=true`、`weightFactor=1.500`

### 2. `M2-F02` 老师评价的验证来源

- 当前可验证部分：
  - 能评价老师
  - 能显示老师评价维度
- 当前已验证部分：
  - `sourceType=trial` 时，后端会通过 `trial_booking.course_id -> course.coach_id` 验证老师来源
  - `sourceType=checkin` 时，后端会通过 Workshop 签到和 Workshop 关联教练验证老师来源
- 结论：
  - 老师可信评价可通过补库准备履约事实后，再走 M2 创建评价接口验证
  - 不能只补 `review.is_verified` 直接当成功能通过

### 3. `M2-F03` 课程评价的验证来源

- 当前最适合做跨模块联验的一项。
- 最小联验链路：
  - `M1` 先准备试听记录
  - 状态进入 `confirmed`、`attended` 或 `no_show`
  - `M2` 再提交课程评价
  - 看返回结果中的 `isVerified`

### 4. `M2-F08` 商家/教练申诉与平台审批

- 至少分三段验：
  - 普通用户或对应主体发起申诉
  - 具备角色的账号能否访问对应入口
  - 管理员审批后评价状态是否改变
- 不能只看“数据库里多了一条申诉记录”，因为那无法证明审批约束和状态流转正确。

### 5. `M2-F07` 复杂风控

- 当前真正能验的是基础风控：
  - 新号降权
  - 重复评价转 `pending`
- 立项书要求但当前未形成完整闭环的部分：
  - 相似文案
  - 设备/IP
  - 异常聚集
- 结论：
  - 这部分应标为跨模块且待增强，不能通过补库判定通过。

### 6. `M2-F06` 真实媒体上传闭环

- 可以拆成两种验收口径：
  - 弱口径：媒体已挂接并可显示
  - 强口径：上传、挂接、预览、审核、删除完整闭环
- 当前若走联调验收，务必明确你们验的是哪一种。

## 建议联调顺序

1. 先做 `M1-F08 -> M2-F03/M2-F04` 的试听来源联验。
2. 再做 `M3/M7/管理员 -> M2-F08` 的申诉审批联验。
3. 最后单独评估 `M2-F06` 真实媒体链路与 `M2-F07` 复杂风控，不要和基础评价主链路混验。

## 本清单结论

- 当前已完成验证的跨模块链路：
  - `试听预约 -> 已验证课程/舞室/老师评价`
  - `Workshop 订单/签到 -> 已验证舞室/老师评价`
  - `评价 -> 商家/教练回复 -> 已回复回显`
- 仍不能高估为完成的跨模块链路：
  - `活动结束后自动邀请评价`
  - `平台管理员审批申诉后驱动评价状态迁移`
  - `真实对象存储上传、审核、删除`
  - `设备/IP/相似文案/异常聚集` 等复杂风控
