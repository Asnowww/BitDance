## S1：`/search` 语义收敛首批整改

### S1-1 伪搜索框改为结果摘要

- 优先级：P0
- 问题：顶部控件长得像搜索框，但点击后返回上一页。
- 目标：去掉“像输入、却不能输入”的伪语义。
- 变更文件：
  - `frontend/src/pages/home/SearchPage.vue`
- 实施结果：
  - 改成非输入样式的结果摘要卡。
  - 展示“附近找到多少家舞室”和“当前选择提示”。
- 验收标准：
  - 页面顶部不再冒充可编辑搜索框。
  - 用户看到的是结果摘要，而不是误以为自己能改关键词。
- 当前状态：已完成

### S1-2 筛选状态与筛选动作分离

- 优先级：P0
- 问题：`舞种 / 距离 / 价格 / 时段 / 舞室` 看起来像五个独立筛选器，实际统一打开一个总抽屉。
- 目标：把“当前已生效条件”和“打开筛选抽屉”明确分开。
- 变更文件：
  - `frontend/src/pages/home/SearchPage.vue`
  - `frontend/src/components/studio/StudioFilterDrawer.vue`
- 实施结果：
  - 搜索页改为“当前筛选”状态 chips。
  - 单独提供 `筛选` 按钮打开抽屉。
  - 去掉最近点击态冒充生效态的 `activeFilter` 逻辑。
- 验收标准：
  - 状态 chips 不再承担动作入口语义。
  - 用户能明确区分“现在生效了什么”和“点哪里去改条件”。
- 当前状态：已完成

### S1-3 收藏和对比必须依赖显式选择

- 优先级：P0
- 问题：底部收藏按钮会在未明确选择对象时默认作用到第一条结果。
- 目标：禁止隐式默认动作。
- 变更文件：
  - `frontend/src/pages/home/SearchPage.vue`
  - `frontend/src/components/pen/PenActionBar.vue`
- 实施结果：
  - 底部操作栏增加可禁用态。
  - 收藏按钮要求只选中 1 家舞室。
  - 对比按钮要求至少选中 2 家舞室。
  - 列表尾部选择控件改成显式 `选中 / 已选` 文案。
- 验收标准：
  - 无选择时，收藏和对比都不会悄悄作用到默认对象。
  - 用户能一眼看懂“我现在有没有选中对象”。
- 当前状态：已完成

### S1-4 去掉“整卡点击 + 查看详情”重复语义

- 优先级：P1
- 问题：结果卡整卡可点击，同时卡内又用“查看详情”承载同一含义。
- 目标：减少重复动作语义。
- 变更文件：
  - `frontend/src/pages/home/SearchPage.vue`
- 实施结果：
  - 结果卡保留整卡进入详情。
  - 卡内改为中性说明文案，不再伪装第二个详情按钮。
- 验收标准：
  - 用户不会误以为卡内还有不同于整卡点击的第二主动作。
- 当前状态：已完成

## S2：`/search` 第二批补强任务

### S2-1 增加真正的“改关键词/改城市”入口

- 优先级：P1
- 目标：让搜索结果页不只是“附近结果摘要”，而是真能回到搜索条件编辑。
- 建议实现：
  - 在顶部摘要区增加“修改搜索”次级入口，或跳回独立搜索输入态。
  - 若当前没有独立搜索输入页，则至少补“城市/关键词”编辑浮层。
- 验收标准：
  - 用户能从 `/search` 自己发起新搜索，而不必靠浏览器返回。
- 当前状态：已完成

### S2-2 地图点位与列表高亮联动

- 优先级：P1
- 目标：用户在地图上点中舞室时，不要只能直接跳详情，也能知道它在列表里的对应对象。
- 建议实现：
  - marker 点击先高亮同 ID 列表项，再由用户决定进入详情。
  - 列表点击也同步更新地图选中态。
- 验收标准：
  - 地图和列表不是两套平行视图，而是同一结果集的双视角。
- 当前状态：已完成

### S2-3 对比页入口与选择上限反馈

- 优先级：P1
- 目标：让用户更清楚“最多选 3 家”以及当前已选数量。
- 建议实现：
  - 在搜索页显式显示 `已选 x/3 家`。
  - 第 4 次选择时给出明确反馈。
- 验收标准：
  - 对比上限、当前数量、下一步动作都足够直白。
- 当前状态：已完成
