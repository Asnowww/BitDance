# M7 商家/教练运营端开发规格

## 1. 目标

M7 的目标是在现有 BitDance 手机 H5 框架内，补齐舞室管理员、教练、平台管理员的运营闭环能力，达到真实前后端联调可用的 B 级交付标准。

本阶段不做桌面后台，不接真实第三方支付，不生成真实结算单和提现流程。正式课与 Workshop 支付均使用模拟支付按钮，点击后调用后端 pay 接口完成支付状态流转。

## 2. 角色

### 2.1 角色类型

- 舞室管理员：通过舞室认领或新舞室入驻审核后获得。
- 全职教练：由舞室管理员邀请绑定，课程收益归舞室。
- 签约教练：由舞室管理员邀请绑定，收益按合作协议分成。
- 自由教练：通过个人教练资质审核后获得，可独立发布 Workshop。
- 平台管理员：保留审核能力，并在 H5 中提供轻量审核页。

### 2.2 权限矩阵

| 功能 | 舞室管理员 | 全职教练 | 签约教练 | 自由教练 |
| --- | --- | --- | --- | --- |
| 编辑舞室信息 | 可 | 不可 | 不可 | 不可 |
| 管理课程 | 可 | 仅自己负责课表 | 仅自己负责课表 | 不可 |
| 发布 Workshop | 可直接发布 | 需舞室审批 | 需舞室审批 | 资质通过后独立发布 |
| 查看舞室数据 | 可 | 部分 | 不可 | 不可 |
| 管理教练账号 | 可 | 不可 | 不可 | 不可 |
| 回复评价 | 本舞室、课程、绑定教练相关评价 | 仅自己相关评价 | 仅自己相关评价 | 仅自己相关评价 |
| 正式课核销 | 本舞室全部正式课订单 | 自己负责场次 | 自己负责场次 | 自己负责场次 |
| Workshop 核销 | 本舞室全部 Workshop 订单 | 自己负责 Workshop | 自己负责 Workshop | 自己创建的 Workshop |
| 收益归属 | 舞室 | 舞室 | 按协议 | 教练本人 |

## 3. 业务规则

- 舞室入驻须提交营业执照等资质，经平台管理员审核通过后开通商家后台。
- 用户可认领已有舞室，也可创建新舞室草稿并提交入驻审核。
- 新舞室审核前不出现在用户端搜索，只在申请人自己的进度页可见。
- 新舞室审核通过后：`studio.status=active`、`studio.claim_status=claimed`，申请人绑定 `STUDIO_ADMIN`。
- 教练账号须由舞室管理员邀请绑定，或通过独立教练资质审核。
- 教练邀请流程：商家发起邀请并设置分成比例，教练接受/拒绝；后续商家可调整或终止合作，调整立即生效。
- 自由教练资质审核通过后可独立发布 Workshop，不再逐条平台审核。
- 全职/签约教练发布 Workshop 需要舞室管理员审批。
- 自由教练发布的 Workshop 不需要绑定舞室；全职/签约教练发布的 Workshop 必须绑定舞室。
- 商家不可直接删除评价，只能回复评价或发起申诉，评价申诉由平台审核。
- 收益统计按归属规则计算应归属收入，但 M7 不生成结算单、不提现。

## 4. 数据库设计

所有迁移必须非破坏性。禁止删除现有业务数据。上线前先备份云库。

### 4.1 现有字段可复用

`studio` 已具备大部分入驻字段：

- `studio_name`
- `brand_name`
- `city_id`
- `business_district_id`
- `address`
- `longitude`
- `latitude`
- `contact_phone`
- `intro`
- `business_hours jsonb`
- `claim_status`
- `status`

`studio_dance_style` 可用于舞室舞种绑定。

`studio_claim.business_license_asset_id` 可用于营业执照/证明材料。

建议新增/补齐：

```sql

ADD COLUMN IF NOT EXISTS file_name varchar(255),
ADD COLUMN IF NOT EXISTS mime_type varchar(100),
```

### 4.3 正式课订单状态

- `pending_payment`：待支付
- `paid`：已支付，已生成 8 位数字核销码
- `refund_requested`：退款待商家审核
- `refunded`：已退款
- `refund_rejected`：退款被拒
- `checked_in`：已核销
- `completed`：已完成
- `canceled`：待支付取消

### 4.4 Workshop 状态

- 舞室管理员创建：可直接 `published`
- 全职/签约教练创建：`pending_approval`，由舞室管理员审批
- 自由教练创建：资质已通过时可直接 `published`
- 支持 `offline`

### 4.5 媒体上传

M7 使用数据库存储文件内容：

- `media_asset.content bytea`
- 单文件最大 5MB
- 允许 `jpg/png/webp/pdf`
- 营业执照允许 PDF
- 头像/封面只允许图片

## 6. 前端设计标准

### 6.1 总体原则

- 继续使用手机 H5，不做桌面后台。
- 商家端也放在 `/coach/*` 路由下。
- 复用现有 BitDance 主体框架、`PenTopBar`、`PenFieldRow`、`AppLayout`、Vant。
- 统一运营工作台首页提供角色切换：舞室管理员 / 教练 / 平台管理员。
- 页面必须真实接后端接口，禁止继续使用静态列表伪造业务状态。
- 表单必须有 loading、empty、error、success、disabled 状态。
- 关键操作必须二次确认：下架、取消、退款审核、核销、拒绝审核、终止合作。

### 6.2 路由

建议新增或改造：

- `/coach/dashboard` 运营工作台
- `/coach/studio-claim` 舞室认领/新舞室入驻
- `/coach/studio-claim/status` 审核进度
- `/coach/courses` 课程管理
- `/coach/course-edit/:id?` 课程创建/编辑
- `/coach/schedule` 周课表管理
- `/coach/schedule-edit/:id?` 场次创建/编辑
- `/coach/schedule/:id/bookings` 预约/订单名单
- `/coach/orders` 订单中心
- `/coach/checkin` 核销
- `/coach/workshops` Workshop 管理
- `/coach/workshop-create`
- `/coach/replies` 评价回复
- `/coach/settlement` 收益统计
- `/coach/platform/reviews` 平台审核中心

### 6.3 页面设计

#### 运营工作台

- 顶部展示当前角色
- 核心指标卡片：收入、订单、核销、退款、待回复、评分。
- 快捷入口：课程、课表、订单、Workshop、评价、收益、审核。

#### 舞室入驻/认领

- Tab：认领已有舞室 / 创建新舞室。
- 创建新舞室字段：舞室名称、品牌名、城市/商圈、地址、经纬度、电话、舞种、简介、营业时间、营业执照/证明材料。
- 进度页展示：pending / approved / rejected，并支持被拒后重新提交。

#### 课程管理

- 列表支持状态筛选：草稿、已发布、已下架。
- 表单字段覆盖课程字段和试听配置。
- 支持发布、下架、编辑。

#### 周课表

- 7 天视图。
- 支持新增/编辑/取消场次。
- 场次卡片展示课程、教练、教室、时间、容量、已预约。
- 可进入预约/订单名单。

#### 订单中心

- Tab：正式课订单 / Workshop 订单 / 退款 / 核销历史。
- 支持按状态筛选。
- 支持手动输入 8 位码核销。
- 扫码入口先保留 H5 能力；扫码结果最终落到 8 位数字码。
- 异常提示：过早、过期、已核销、退款单、无权限。

#### Workshop 管理

- 列表展示发布状态、审核状态、报名数、收入。
- 创建页支持多个场次，每场可单独设置价格和容量。
- 根据角色自动决定是否进入审批。

#### 评价回复

- 筛选：全部 / 待回复 / 已回复。
- 展示评分、评价目标、评价内容、已有回复。
- 支持多条回复和删除。
- 展示“官方回复”标签。

#### 平台审核中心

- Tab：舞室 / 教练 / Workshop / 评价申诉。
- 每类支持详情查看、通过、拒绝、填写备注。

## 7. 当前项目已知技术缺口

- 前端 `coachOps.ts` 目前请求 `/coach/...`，后端实际多为 `/h5/coach/...` 或 `/merchant/...`，必须统一。
- 前端多个 coach 页面仍是静态数据，需要改成真实接口。
- 后端 `Studio` 实体缺 `business_hours`、`navigation_address` 等写入映射。
- 后端缺课程 CRUD、课表 CRUD、正式课订单实体与接口。
- 后端看板收入目前是简化值，需要接正式课和 Workshop 订单统计。
- 后端 `ddl-auto=validate` 可能被 PostgreSQL 数组字段类型校验卡住；联调可用 `none`，长期应修实体映射。

## 8. 验收标准

### 8.1 后端

- `mvn test` 通过。
- 云库迁移 SQL 非破坏性执行成功。
- 后端可连接云 PostgreSQL 启动。
- Swagger 可访问。
- 核心接口返回统一响应结构。
- 权限越权操作返回明确错误。

### 8.2 前端

- `npm run type-check` 通过。
- `npm run build` 通过。
- `VITE_USE_MOCK=false` 下核心页面可用。
- 运营工作台、课程管理、课表、订单、核销、评价、审核中心均能真实请求后端。

### 8.3 业务链路

必须跑通：

1. 新舞室入驻提交 -> 平台审核通过 -> 进入商家工作台。
2. 商家邀请教练 -> 教练接受 -> 关系生效。
3. 商家创建课程 -> 创建课表 -> 用户下正式课订单 -> 模拟支付 -> 商家核销。
4. 商家创建 Workshop -> 用户下单 -> 模拟支付 -> 核销。
5. 全职/签约教练创建 Workshop -> 舞室审批 -> 发布。
6. 自由教练资质审核通过 -> 独立发布 Workshop。
7. 商家/教练回复评价。
8. 看板展示本月收入、订单、核销、退款、预约、报名、待回复、评分。
