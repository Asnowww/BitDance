# 开发历史记录

## 项目概览

- 项目名称：BitDance
- 一句话定位：面向舞蹈学习者的找舞室、选课程、约搭子、记成长一站式平台
- 当前版本/里程碑：MVP（阶段 A 收尾、阶段 B 启动）
- 主要负责人：第五组（组长：顾远）

### 技术栈

- 用户/教练前端：Vue 3 + Vite 5 + TypeScript + Pinia + Vue Router (hash) + Vant 4，小红书视觉风格主色 `#FF2442`，移动端 H5（375 设计稿，最大宽度 480px 居中），后续以 Capacitor 打包 Android APK
- 管理端前端：Vue 3 + Vite + TypeScript（独立工程，桌面端），承载舞室管理员与平台管理员后台
- 后端：Spring Boot 3 + Java 21，模块化单体
- 数据库：PostgreSQL 云库（98.142.241.155:5432，schema bitdance）
- 缓存：Redis（待引入）
- 关键依赖：axios、postcss-px-to-viewport-8-plugin、unplugin-vue-components + VantResolver、Capacitor（后续阶段引入）

### 架构与目录

仓库根目录下：`frontend/` 用户/教练 H5 工程，`backend/` 后端工程（待初始化），`docs/history/` 历史归档目录，参考文档与 schema 位于根目录。详见 `BitDance_architecture_mvp.md`。

## 约定与规范

见 SKILL bitdance-dev 第 7 节与 `BitDance_后端代码规范文档.md`。前端额外约束：

- 路由强制 hash 模式，禁止切换为 history 模式，否则后续 Capacitor 打包 APK 会失效。
- 视觉风格统一参照小红书：主色 `#FF2442`、瀑布流首页、沉浸式详情页、底部 TabBar 中央凸起发布按钮。
- 接口统一通过 `src/utils/request.ts` 调用，业务接口拆分到 `src/api/<domain>.ts`，mock 数据集中在 `src/mock/modules/<domain>.ts`。
- 组件文件 PascalCase.vue；store / composable / 工具方法 camelCase；样式以 SCSS 模块化，主题变量集中在 `src/styles/variables.scss`。

## 禁区与陷阱

- 不要修改 `bitdance_postgresql_schema.sql` 中已使用表的字段类型，只允许新增字段或新增表。
- 前端路由必须保持 hash 模式，否则后续 APK 打包会失效。
- `VITE_USE_MOCK` 切换前必须确认所有接口在真后端已实现，否则页面会大面积报错。
- 云数据库凭证不得 push 到公开仓库；本地配置走 `application-local.yml`，并已在根 `.gitignore` 内。
- `.claude/` 目录已在根 `.gitignore` 内忽略，提交前 `git status` / `git diff --cached` 必须自查一遍，禁止把 worktree、settings.local.json、skill 内容入库。
- 提交署名只写人类成员，禁止出现 ChatGPT / Claude / Anthropic / OpenAI / Copilot / Cursor / AI / LLM / agent 等任何 AI 工具或机器协作者标识。

## 接口与数据契约

### 主要 API

由 Architect Agent 在每个功能点开发前补全，记录在该区块。当前已约定：

- `POST /auth/sms/send`：手机号短信验证码发送，请求体 `{ phone }`，响应 `{ sent, expiresIn }`。
- `POST /auth/login`：手机号 + 验证码登录，请求体 `{ phone, code }`，响应 `{ token, user }`，其中 `user = { id, phone, nickname, avatar, roles }`。
- `GET /studios/nearby`：附近舞室列表，参数 `latitude / longitude / city / page / pageSize / sort`，响应 `{ list, page, pageSize, total }`，列表项含 `id / name / cover / city / area / distanceKm / ratingAvg / reviewCount / topStyles / beginnerFriendly`。
- `GET /studios/{id}`：舞室详情，附 `intro / address / openHours / photos / courses`。

### 数据库表结构

以 `bitdance_postgresql_schema.sql` 为准。

### 模块间通信

前后端通过 RESTful + Bearer token，统一返回 `{ code, message, data, traceId }`，前端拦截 `code === 0 / 200 / 'SUCCESS'` 视为成功。

## 决策记录

### 2026-05-09：用户端与教练端统一为 Vue H5 移动端，不再开发微信小程序

- 决策内容：用户端与教练端共用同一份 Vue 3 + Vite + TS + Vant H5 工程，先以浏览器 H5 上线，阶段 B 收尾后使用 Capacitor 打包为 Android APK 分发。
- 上下文与权衡：原方案双轨开发微信小程序与 Web 管理端，资源不足；统一为 H5 后失去微信生态原生入口与订阅消息能力，但获得跨平台一致性与更短交付周期，符合实训项目优先验证“是否有人在平台上做决策”的目标。
- 影响范围：架构文档（已修订）、API 路径（新增 `/api/h5/**`，保留 `/api/mp/**` 双写过渡）、登录方式（MVP 阶段以手机号验证码为主，微信登录降级为可选项）、消息通知（订阅消息降级为站内信 + 浏览器通知 + 后续 APK 推送）。
- 回滚条件：若实测中 H5 体验在低端 Android 设备或浏览器内核上无法满足核心交互，且 Capacitor 打包 APK 仍不能解决，则评估退回到微信小程序或独立 React Native / Flutter 方案。
